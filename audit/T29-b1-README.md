# T29 B1：作答前人工标注

- 范围：`eval-v1.2` 的 109 道 deterministic 题；不含 13 道 judge 题。
- 标注：Codex 先逐题阅读题面、参考 SQL、L1 与 L1plus 的明确约定，再写入 `T29-build-b1.py` 的逐题理由和解读清单。此阶段没有读取模型作答、思考内容或逐题评分日志，也没有付费调用。脚本只是物化人工标注和参考结果，不进行自动歧义识别。
- 用户裁决（2026-10-25）：B2 只认可符合 L1plus 明确约定的理解。题面允许但违反明确约定的解读单列，不进入 B2；既有参考若违反约定，只标记“参考答案可疑”，主评分不动。
- 主文件：`T29-b1.json`。每题有题面、人工理由、题面多解标记、符合约定的多解标记、每种解读及参考 SQL、结果路径和 SHA-256。
- `sql` 与 `result` 记录原有冻结参考及其来源；原 SQL 为选择域而非最终答案时，另有可直接执行的 `answer_sql` 与 `answer_result`，不把选择域当作答案。
- 新结果：`T29-b1-results/*.json`，含列类型和完整结果。它们是私有参考答案，不复制到主仓库。

## 参考结果生成与核验

在主仓库 T29 clone 的既有 uv 环境中执行（不安装新依赖）：

```sh
export UV_CACHE_DIR="$TMPDIR/uvcache"
uv run --offline python "$SEMDEBT_DATA_DIR/t29-b1-eval/audit/T29-build-b1.py"
```

只打开 `$SEMDEBT_DATA_DIR/chdb-eval`，单进程串行执行；遇错显式停止，不重试、不打开其他 chDB 数据目录。生成过程中两次 SQL 构建失败：第一轮 Q118 的 `any(total_sales) AS total_sales` 导致 ClickHouse 别名替换后嵌套聚合；第二轮 Q119 的 `sum(amount) AS amount` 在窗口排序引用中发生同类冲突。改为不冲突的别名后第三轮全部执行成功。这些是免费参考 SQL 构建的失败，未发生模型调用或实验作答。

核验：109 个题号唯一且与冻结 deterministic 题集完全相等；所有原参考、新结果及 SQL 的 SHA-256 逐项相符；每题至少一种 B2 可认可理解。7 份选择域最终答案物化中，Q84 两份、Q98 两份、Q100、Q118 用现有 v2 比对均为 correct。Q119 用 v2 比对返回 selection；另按 StoreKey×ProductKey 核对，310 行对象集合与原 CSV 完全一致，310 行公司排名也全部一致，未为此改动评分器。该现象留作后续 B2 接线时复核，不能把本次比对写成7/7评分器通过。
